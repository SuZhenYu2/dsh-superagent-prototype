# 数据源：GitHub 与飞书

## 边界与共同机制

Source 将外部事件转换为统一的 Trigger，提供监听范围、发送渠道、线程上下文、执行环境变量和健康状态；是否允许发起工作仍由准入策略及后续评估决定，**收到消息不等于创建工单**。[SourceKind 接口](../src/sources/kind.ts)和[注册表](../src/sources/registry.ts)定义这些扩展点：插件注册类型，注册表解析配置、验证来源策略，并向引擎提供 scope。来源禁用或配置无效时不监听；配置存在而插件缺失时也不会错误地放行。

[SourceContext](../src/sources/host.ts)把接收入口、命令、状态、线程与工单访问能力交给来源。来源状态的键集中定义在 [KV](../src/kv.ts)，游标与已处理记录因而能跨进程重启保存。两种来源都借助确定性的 Trigger ID 对重叠读取去重；共享[轮询工具](../src/sources/poll.ts)将游标回退 5 秒，以容忍远端事件延迟。订阅线程只要有活跃工单便继续轮询；否则在最近触发或关联工单结束后的 14 天内轮询。

## GitHub

### 配置与事件范围

[GitHub 来源](../src/sources/github.ts)使用已登录智能体账号的 `gh` 命令监听指定 `owner/name` 仓库。默认轮询间隔为 60 秒，可配置 60–3600 秒，实际还要服从 GitHub 返回的更长间隔；默认连续三轮失败才报告来源异常。可分别开启仓库范围的新 Issue、新 PR、评论和默认分支 CI 观察；这些开关默认关闭，开启时从当前时间建立基线，不回放此前的仓库事件。

来源策略配置允许发起工作的账号，以及可产生推断候选的机器人名单。名单中的人 @ 智能体可形成明确请求；机器人评论只可能成为推断候选，不能作为明确请求或停止工单。监听范围与发送者权限是两个独立判断，具体映射见 [githubKind](../src/sources/github.ts) 和[准入逻辑](../src/admission.ts)。

### 轮询与恢复

每轮依次读取账号通知、已启用的仓库事件流、开放工单关联的 PR 及其 CI、订阅线程；不同流和线程的失败尽量隔离，整轮结束后汇总错误。通知会过滤仓库，按 Issue/PR 读取正文与讨论；同一轮同一个 PR 的读取通过 Promise 缓存共享。普通评论、行内评论和 review 分别读取，无正文的 review 决策也可形成触发。事件转换规则见 [github-trigger.ts](../src/sources/github-trigger.ts)，PR 观察和关联见 [github-pull.ts](../src/sources/github-pull.ts)。

仓库流维护开始时间、游标及适用时的 ETag，按更新时间递增处理；未变化时可通过条件请求得到 304。读取中断时不推进该流游标。默认分支 CI 首次仅建立失败集合基线，之后失败集合变化才触发；当前没有失败但仍有检查运行时沿用旧失败，当前已有失败时则使用当前失败集合。PR CI 首次建立指纹，后续快照变化产生递增版本的 Trigger。

通知读取失败的 Issue/PR 会存入重试表，下轮优先处理；通知游标与重试表在同一事务更新。HTTP 404 可能意味着私有仓库权限丢失，仍重试；410 视为删除，停止该通知重试。持续失败满 24 小时也停止该通知重试，但保留线程错误和原读取位置，之后的新通知或线程轮询仍可能补回。相关实现见 [pollRound 与 pollNotifications](../src/sources/github.ts)。

### 读取与回复

[github-read.ts](../src/sources/github-read.ts)提供线程上下文、PR 检查等读取能力；[github-channel.ts](../src/sources/github-channel.ts)负责发送与链接。来源向执行器暴露仓库、智能体账号、提交邮箱、来源 Issue/PR 编号及 PR head ref；具体值以 [environment 定义](../src/sources/github.ts)为准，而不是把凭据塞进提示词。

## 飞书

### 配置与准入

[飞书来源](../src/sources/feishu.ts)使用仅允许 bot 身份的 `lark-cli` 配置。指定群可选择仅接收 @ 或全部消息；其他群默认为不接收，可改为仅 @；私聊默认接收。接收全部消息需要机器人具有相应读权限。私聊和 @ 的接收范围仍与允许发起工作的用户名单分开；名单内人员私聊或 @ 是明确请求，允许的其他机器人消息只能成为推断候选。

允许用户可通过指定群同步：读取完整用户成员列表后替换名单，保留既有成员顺序并更新名字；返回不完整列表时拒绝同步，避免意外移除用户。回复前再次检查目标会话是否仍在来源监听范围内。

### 实时消费与历史补收

[feishu-loops.ts](../src/sources/feishu-loops.ts)并行运行事件消费、历史补收和群名刷新。实时消费者启动 `lark-cli event consume im.message.receive_v1 --as bot`，逐行串行处理事件；45 秒未 ready 会停止进程，单行字符串长度超过 1,048,576 个 UTF-16 代码单元会报错，此限制不是按字节计算。进程异常退出后从 1 秒开始指数退避，最多 60 秒；若上次运行至少一分钟则重置到 1 秒。禁用来源后检查器会停止消费者。

历史循环约每分钟扫描配置群和已知私聊：首次只记录起点，后续按时间窗口读取群消息与活跃话题，再推进回退 5 秒的游标。分页不前进或结果越出请求的群/话题会报错并保留游标；畸形条目跳过并计数。旧话题超过 14 天且没有仍在轮询的订阅时清理。订阅线程另行读取回复，以已见消息 ID 防重，首次先标记根消息与父消息，避免把历史上下文误当新事件。实时和历史事件转换见 [feishu-trigger.ts](../src/sources/feishu-trigger.ts)。

群名每分钟独立刷新，失败时沿用旧值；事件消费者、历史循环和各线程分别呈现健康或错误信息。[feishu-read.ts](../src/sources/feishu-read.ts)提供线程分页读取，[feishu-image.ts](../src/sources/feishu-image.ts)处理图片，[feishu-channel.ts](../src/sources/feishu-channel.ts)负责消息和链接。来源向执行器提供机器人标识与来源群 ID，不提供凭据。

## 排查入口

- 接收异常：先检查来源启用、CLI 身份和权限、scope 配置，再看来源健康状态与线程 `pollError`。
- 缺少历史：检查来源首次启用基线、14 天轮询窗口、游标和外部接口权限；不要假设系统会无限回溯。
- 回复异常：区分来源不再监听、目标永久不可达与临时发送失败；发送持久化和重试见 [执行与存储](04-execution-storage.md)。
